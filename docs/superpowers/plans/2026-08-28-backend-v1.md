# Spenden-Transparenz Backend v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the read-only public API and the idempotent ingestion pipeline that turn ReliefWeb reports and the 44-org pilot dataset into a provenance-carrying Response Board for the Nepal 2026 flood.

**Architecture:** One Postgres database; one shared model/settings package (`packages/core`) that only the backend lead writes; a FastAPI read-only API (`apps/api`, one router per file) that serialises every provenance-carrying value as the same `datum` object; and a set of idempotent Python jobs (`pipeline`) that each open an `ingestion_run`, upsert on natural keys, never delete, and write zero rows on a second identical run. Extraction runs an LLM over report body text and passes every produced claim through a verbatim gate before it may become a row.

**Tech Stack:** Python 3.13, FastAPI 0.141, SQLAlchemy 2 (async, `asyncpg`), Alembic (sync, `psycopg`), pydantic-settings, `python-json-logger`, `slowapi`, `openai` client against OpenRouter, pytest + httpx `ASGITransport` + `pytest-httpserver`, Postgres 16, `uv` locally, hash-pinned `requirements.txt` per service, ruff (line-length 120), GitHub Actions, Railway (EU-West).

**Spec:** `docs/superpowers/specs/2026-08-28-v1-katastrophenmodus-design.md` — binding. Read it before this plan. Project conventions: `CLAUDE.md`. Data contract: `SCHEMA.md` + `schema/org.schema.json`.

## Global Constraints

Every task's requirements implicitly include this section.

1. **No org score, grade, rank, or rating anywhere** — not in a column, not in a computed field, not in an API response, not in a sort key. Verification filters are SQL over datums; sorting is by recency or name only.
2. **Provenance invariants** (tests enforce them): a datum with `value IS NOT NULL` has a `source_url`; a datum with `value IS NULL` (a gap) has a `note` AND a `gap_reason`; a record's `data_gaps` is a superset of its null paths; a quote is at most 40 words and appears verbatim in its source text.
3. **`report.body_text` is third-party copyright.** It is stored for extraction only and must never appear in any API response model, any log line, or any file under `data/`. What ships is the quote plus the link.
4. **No natural persons in the database.** No trustee names, no author e-mails, no contact persons. `data/raw/ukcc_api/charitytrusteeinformation_*.json` is gitignored and already removed from the tree; it must not be read by any job.
5. **Server-side fetchers use a host allowlist.** ReliefWeb is rate-limited to at most one request per 2 seconds with an honest User-Agent. `validate_orgs.spotcheck()` stays CLI-only and is never reachable from the API.
6. **Secrets only from the environment or `./.env.spenden`** (gitignored). `core.settings` must NOT fall back to `../AthenaRun/.env.platform` for `ANTHROPIC_API_KEY`, `ADMIN_TOKEN` or `DATABASE_URL`. With `ENV=production` the app refuses to start without `ADMIN_TOKEN` and `DATABASE_URL`. Secrets never appear in logs.
7. **Logs are JSON, one line per event, no emojis.** No emojis anywhere in code, comments, log strings, commit messages, or test names.
8. **Files are written with LF line endings.** On Windows, `open(..., newline="\n")`. `.gitattributes` already enforces `* text=auto eol=lf`.
9. **Postgres enums are TEXT + CHECK**, never native `CREATE TYPE`. Enum value lists live in `core/enums.py` and are the single source of every CHECK expression.
10. **Only the backend lead writes `packages/core/**` and `apps/api/alembic/versions/**`.** A worker who needs a model change sends the lead a one-line request and rebases after the lead lands the migration.
11. **Documentation gate:** before writing code against any external library API, look the API up with context7 (`resolve-library-id`, then `query-docs`). Memory is not a source. This is a gate, not a nicety.
12. **TDD:** no production code without a failing test first. Watch the test fail, then make it pass. Before claiming anything is done, run the command and read the output.
13. **Git:** one worktree and one branch per agent, never `git stash`, PR against `main`, merge only on green CI. Every commit message ends with the two trailers:
    ```
    Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>
    Claude-Session: https://claude.ai/code/session_018hf9r9gUZkVw4DcrongBzd
    ```
14. **ruff** with `line-length = 120`, `target-version = "py313"`, rules `E,F,I,B,UP,S,ASYNC,RUF`. `ruff check .` and `ruff format --check .` must both pass.
15. **Not in v1** — do not build: FTS pledge-to-disbursement layer, UK-CC peer distribution or programme-ratio percentiles, statement review UI, auth, user accounts, donate buttons.

```python
def check_in(column: str, values: tuple[str, ...]) -> str:
    """SQL boolean expression for a TEXT+CHECK enum column.

    NULL is intentionally allowed: a CHECK whose expression evaluates to UNKNOWN is satisfied,
    so nullable enum columns need no special case. Values are module constants, never user input.
    """
    quoted = ", ".join(f"'{v}'" for v in values)
    return f"{column} IN ({quoted})"  # noqa: S608 - constants only, no interpolation of caller data
```

```python
from sqlalchemy.dialects.postgresql import JSONB

class OrgDatum(Base):
    __tablename__ = "org_datum"
    ...
    value: Mapped[Any | None] = mapped_column(JSONB, nullable=True)
    is_gap: Mapped[bool] = mapped_column(Boolean, Computed("value IS NULL", persisted=True))

    __table_args__ = (
        CheckConstraint(enums.check_in("value_type", enums.VALUE_TYPE), name="ck_org_datum_value_type"),
        CheckConstraint(enums.check_in("verification", enums.VERIFICATION), name="ck_org_datum_verification"),
```

**Files:** Create `pipeline/jobs/match.py`, `pipeline/jobs/districts.py`

Deliberately separate jobs so a new alias or place name can re-match without paying for extraction again.
- `match_orgs`: `org_name_raw -> alias_norm -> org_alias.org_id`. Exact normalised match only. **No fuzzy matching in v1** — a wrong org attribution is worse than a null one, and `org_id IS NULL` is a designed, visible state ("named but not identified"). Unmatched names are logged with their count so aliases can be added deliberately.
- `resolve_districts`: `where_raw[] -> district_alias -> statement_district(resolution="stated")`; when the statement names no place, inherit the report's districts with `resolution="inherited_from_report"`. The distinction must survive to the API, because "the org said Rasuwa" and "the report was about Rasuwa" are different claims.
- `district_alias` is already seeded by Phase 0's `seed_reference` (160 rows: 77 district names, 77 `<name> district` forms, 6 settlement variants) and `seed_reference.UNRESOLVABLE` lists the six phrases that must resolve to no district at all. WP-B consumes both and adds neither: a new alias is a one-line request to the lead, like a column.

## WP-C — The read-only API

### Task C-1: Session dependency, cache headers, ETag, CORS, rate limit

**Files:** Modify `apps/api/app/deps.py`, `apps/api/app/main.py` (the two lines Phase 0 left marked)

- `Cache-Control`: lists `public, max-age=60, stale-while-revalidate=600`; org detail `public, max-age=300`; meta `public, max-age=3600`; health and admin `no-store`. Implement as a small dependency per router, not as a global guess.
- ETag middleware: hash the serialised body, return `304` with no body when `If-None-Match` matches. Applies to `GET` only.
- CORS: exact origins from `settings.cors_origins`, methods `GET, OPTIONS` only, never `*`.
- Rate limit with `slowapi`: 60/min for `GET`, 5/min for admin. The client key is the first hop of `X-Forwarded-For`, with a comment naming Railway as the trusted proxy — and a test that a spoofed second entry in the header cannot change the key.

### Task C-2: The `datum` serialiser

**Files:** Modify `apps/api/app/schemas.py`

One function turns an `org_datum` row into the `Datum` model, and it is the only place that does. A gap serialises with every key present, `value: null`, `is_gap: true`, and its `note` and `gap_reason` — the key never disappears, because a missing key and a null value read completely differently in a frontend.

- [ ] Test: `serialise_datum(gap_row).model_dump().keys() == serialise_datum(value_row).model_dump().keys()`.

### Task C-3 to C-7: the routers

One router per file, one task each, each with its own contract test:
- `disasters.py` — `GET /v1/disasters`, `GET /v1/disasters/{glide_id}`.
- `responders.py` — `GET /v1/disasters/{glide_id}/responders`, the main page. Filters: `district` (repeatable, `^NP\d{4}$`), `org_type`, `verification`, `hq` (`local|international`), `has_response`, `q` (<= 80 chars, parameterised `ILIKE`, never string-formatted SQL), `sort` (`latest|name` only), `limit` (<= 100), `offset`. Response items carry `org` (nullable), `org_name_raw`, `statements[]` with `activity, activity_type, districts[] (with resolution), happened_on, amount, quote, source{url, publisher, published_at, verification}`, plus `counts` and `flags`. `X-Total-Count` on every list. Organisations with no statement are included, never filtered out, unless `has_response=true` is explicitly passed.
- `orgs.py` — `GET /v1/orgs`, `GET /v1/orgs/{org_id}` (all datums, gaps included), `GET /v1/orgs/{org_id}/history?path=`.
- `statements.py` — the chronological stream, same filter vocabulary as `responders`.
- `meta.py` — `/districts`, `/sources` (with licences), `/enums` (from `core.enums`, so the frontend never hardcodes a list), `/freshness` (latest successful `ingestion_run` per job).
- `admin.py` — `POST /v1/admin/ingest/{job}` and `GET /v1/admin/runs`, both behind `X-Admin-Token` compared with `secrets.compare_digest`. No token configured means 503, never "open".

**One query per request.** The responders endpoint must not issue one query per organisation; build the whole board with a small number of joined queries and group in Python, or the page that is the product is also the slow one. Assert it: the contract test counts emitted statements with an SQLAlchemy event listener and fails above a fixed budget (target: <= 4 for the full board).
